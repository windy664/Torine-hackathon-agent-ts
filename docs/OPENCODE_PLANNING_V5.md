## 改良

- 仍使用 OpenCode 1.18.34、DeepSeek flash、同模块续接与父控制器管理的有界自测，不换底座、不加多代理。
- 规划保持最多两次、120 秒。模型看见与校验器一致的公开文本；可选 sourceRef 指向控制器生成的原文目录，控制器还原 sourceQuote，未在目录中的引用仍拒绝。
- API 校验失败反馈具体 case、step 索引、实际 method/path/status；不猜测期望 HTTP 状态、不静默放宽断言。第二次请求包含被拒 JSON 和精确错误，限 8000 字符。
- 每次规划原文、来源目录、HTTP 状态和校验错误保存在 planning/*.json，权限 0600，脱敏配置密钥，响应上限 80000 字符；进度日志给出证据相对路径。
- 两次规划失败标记 planning_degraded，继续当前公开需求实现和后续包，允许受控开发自测。未生成独立用例的功能始终标为 unchecked，整个本地报告最多 partial；旧包回归成功也不能抵消当前包的验证缺口。
- 保留真实构建、基线数据保护、已冻结有效用例的回归、有限修复。程序正常完成但行为未验证可以交付给平台评测；这不是本地验收通过。模型/控制器进程失败、真实验证基础设施失败仍按原策略停止。

## 验证要求与边界

单元测试覆盖错误 API 字段的修复反馈、来源引用还原、伪造引用拒绝、失败/成功原文留档和密钥脱敏。真实 CLI + 实际 OpenCode + 假网关覆盖两项入口、API 错误后恢复、连续两包无有效计划仍进入实现、有效旧用例不能掩盖新包未验证，并检查原基线未被清空。

测试结果以同 ZIP 干净安装验证报告为准。假模型夹具证明控制流程，不证明真实模型会正确实现比赛功能；v5 正式运行是否提分仍待平台结果。
