## 机制

- 保留 OpenCode 1.18.34、同模块会话续接和独立冻结验收，不引入 Pi/DSH、多智能体或新付费服务。
- 插件提供 `torine_app(start/status/stop)`，父控制器持有服务进程。每回合临时控制端点仅绑定 loopback 并使用随机凭据；模型工具参数无控制凭据。
- 应用运行在私有源代码/数据副本；依赖目录只复用，不让模型在诊断工具里安装依赖。随机端口避开评测端口，默认 30s 就绪、180s 租期；就绪轮询单请求也限时，持续读取服务两路输出。
- `torine_check` 在副本执行有限检查，继承 BASE_URL、不继承模型凭据；pipefail、默认 60s/最高 120s、退出码/信号/超时/中断/输出回执。失败和超时作为工具错误反馈，不授予需求通过。
- 普通 Bash 默认 60s、显式上限 120s；拦截常见后台启动和 kill/pkill/killall，提示使用受控服务工具。此命令模式检查不是完备 shell 解析，更不是 OS 沙箱。
- 服务租期到期会先中断尚在执行的检查，再清理进程，不能被挂起检查挡在串行队列后。回合正常退出或超时都清理所属服务，TERM→KILL，只处理本轮进程组；清理异常不假报成功，保留证据。
- 正常工具开始/完成也输出 INFO 简明事件，含需求、阶段、会话、工具与目标。详细参数仍在 DEBUG；错误计数与成功完成计数分开。
- stdout 保留结构化进度，stderr 同步脱敏可读行。心跳区分等待模型/工具/控制器，含等待时长及当前命令；90s 以上输出警告。活动和 token 都不等于业务进展。费用估算与平台结算仍分开。
